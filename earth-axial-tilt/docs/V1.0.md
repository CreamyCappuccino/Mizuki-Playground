# v1.0.0-rc.1 — readable, reproducible release candidate

This incorporates [v0.9](V0.9.md) and the planned release-quality work. **Physical iPhone/Safari acceptance is still open**, so the package and UI say RC rather than silently marking the original release gate complete. [Release checklist](RELEASE_CHECKLIST.md).

## Shipped in the candidate

Basic/All is a presentation preference; it hides optional appearance/guide/instant-value panels without changing experiment values. The short introduction is dismissible and can be opened again. The header identifies the single/dual, close-up/orbit and active clock modes. Japanese and English remain views of the same state.

Compare and Atlas load only when opened. A failed optional module leaves the primary app usable and offers an explicit page reload, because a browser can cache a failed module import. The code is split into application, Three core and renderer chunks. No new runtime library was added. The actual npm-generated lock includes platform-specific optional dependencies; npm ci is used by CI.

Observers, DOM listeners, language subscriptions, RAF, thermal workers and Three resources have explicit cleanup. A bfcache-preserved page is not disposed. Comparison shares GPU resources and uses bounded colour/thermal caches; this is not a claim of zero CPU or constant memory under every browser.

Document link checks, unique HTML IDs, static Japanese keys and conflict markers run before tests. A pinned Chromium-only Japanese comparison-panel image is used for static UI regression after its captured image is reviewed; this is not a GPU-independent golden of every 3D pixel. Numerical geometry and captured A=B regions complement those checks.

## QA boundaries

- Ubuntu 24.04 Chromium: complete browser suite, including earlier feature flows. The native swipe test uses Chromium CDP; WebKit tests a real tap and programmatic scroll isolation because mobile WebKit automation supports neither CDP touch nor a mouse wheel. Native iPhone swipes remain unverified.
- macOS Playwright WebKit: selected Atlas, Focus, i18n, comparison and release flows, serialised with a fresh browser process per test file to bound the lifetime of hosted GPU contexts. Rendering errors are still test failures.
- Actual iPhone Safari: **not yet observed**. Engine tests and emulated viewports do not close this gate.
- Container: unit/type/build checks run on the copied exact source and dependency graph. This container blocks browser navigation to the local preview URL, so it is not the source of the real app screenshots; CI captures are.

Screenshots and traces are saved by GitHub Actions. The exact head SHA and run conclusions must be checked for the final candidate. No public website deployment or GitHub release publication is performed.

## Deliberate scope choices

No new weather/climate model, cloud evolution or continuous expensive Sun animation. Daylight and energy remain separate from decoration. The original large text is retained. Single and comparison use explicitly different page layouts, avoiding inherited orbit transforms and mobile spacer margins.

README now describes the current app. The prior accumulated README is [history](HISTORY.md); the original plan is [archived](PLAN-v0.8.md). START_HERE and ROADMAP identify current state, future work and unfinished gates separately.

## Browser review fixes

WebKit review found GPU memory pressure while running parallel high-DPR contexts. Redundant texture reuploads and identical framebuffer reallocations are now avoided, and disposal explicitly releases the WebGL context. Serial execution alone still produced intermittent allocation errors after several browser contexts. The macOS runner now ends the browser process between files, retaining each file’s failure status and artifacts; it does not filter GPU errors or retry until green. This bounds test-process lifetime, not proof that every on-device GPU memory issue is solved. A real-pointer selection test uses a calculated screen-pixel angular bound for native event rounding, separate from exact numeric coordinate tests.
