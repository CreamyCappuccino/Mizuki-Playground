# v0.6 — season atlas

## Scope and interaction

This release visualises the existing v0.5 physics over the whole latitude/year domain. It does not change solar formulas, EBM parameters, city presets, dependencies, global temperature conventions or deployment. The existing external decorative Earth texture remains external. No new server or external data request is introduced by the atlas.

Season atlas opens from the location panel in a native modal dialog. Opening pauses playback but preserves day, latitude, longitude, obliquity and rotational phase. Closing does not resume playback. Native dialog focus handling allows Escape/Close and restores the opener; a separate action closes it and invokes the existing location camera view. Existing inline graphs and Comfort/Large typography remain.

The atlas provides three daily-mean metrics: TOA solar irradiance (W/m²), geometric daylight (hours), and model temperature (°C). Selecting a day/latitude changes the underlying globe and numeric readouts. Longitude is retained; when latitude changes the selected point is explicitly renamed Custom latitude rather than falsely retaining Taipei's name. Selecting only the date retains the existing location. Rotation is untouched. Pointer taps/clicks select; hover does not. Movement beyond 8 CSS pixels cancels selection, including a drag that returns to its start. Vertical touch swipes scroll. Native day/latitude sliders provide keyboard and assistive-technology alternatives instead of inventing a two-dimensional ARIA slider.

## Sampling and meaning

The raster has 365 columns (days 1–365) and 91 rows (90°N down to 90°S at 2° intervals). It is an illustration on a linear latitude axis, NOT an equal-area grid; counting coloured pixels is not a global-area statistic. Browser smoothing is only display interpolation. The selected-value text directly calls the same analytic astronomy functions or thermal interpolation as the globe, at the selected latitude/day rather than the nearest raster cell. Pointer selections round the day to a whole day and latitude to 0.1°. Existing locations can retain their more precise latitude. No subdaily temperature is introduced.

The dashed trace is the model solar declination, i.e. subsolar latitude through the year. It is not an isotherm, an ice edge or a temperature maximum. It can be hidden. The circular-model calendar and exact-horizon reporting convention are unchanged (see SCIENCE.md).

**Difference = selected tilt minus 23.44°**, evaluated at the same latitude and day. For temperature, both sides must match the selected model and heat capacity; the reference must actually be a solved 23.44° year. A legacy-model or wrong-depth thermal reference is rejected rather than used. This comparison is model-to-model, not a climate observation or a forecast. Geometry-only metrics remain available if the worker is unavailable. No extra thermal solver runs in the atlas.

Daily solar uses a fixed 0–1361 W/m² scale, daylight 0–24 h. Absolute-temperature colour limits expand to include the entire sampled field, rounded outwards to 5°C. Difference limits are symmetric about zero and rounded outwards. Both adaptive scales are clearly labelled; changing settings can change their limits. Numeric readings are never clipped. The palette is specific to the atlas (it need not be the same as the globe's palette). All-zero differences use a neutral field and a nonzero legend span. Extreme EBM warnings apply to absolute or difference displays whenever either relevant solution leaves the illustrative -60..60°C envelope. An apparently moderate difference is not evidence that either absolute temperature is plausible.

## Lifecycle and cost

The atlas retains just its latest numerical field and layout. The field is rebuilt only for metric/view/tilt changes, or temperature-model/heat-storage/solution changes that actually affect it. Selection movement and trace toggles do not regenerate the raster. Resizing redraws the pixels/labels with real CSS-pixel font sizes; it does not rerun physics. A pending, mismatched or failed thermal configuration clears the previous temperature raster and legend. Error/pending messages never stand in for a calculated temperature.

The existing worker's latest-request handling remains authoritative. It supplies a reference if either the annual comparison or an open temperature-difference atlas needs one. Solar/daylight do not wait for a thermal reference. No raster is computed while the dialog is closed. Raster and crosshair are separate layers; a diagnostic data-field-revision attribute counts actual repaint operations.

## Verification

13 new unit tests cover field shape/orientation/endpoints, zero-tilt constancy, polar day/night, all-zero differences, subtraction semantics, EBM sampling, missing/stale/mismatched temperatures, exact-horizon conventions, unclipped display scales, pointer quantisation, invalid inputs, and neutral palette colours.

6 new Chromium tests cover modal/globe selection, neutral Earth differences and matched heat storage, keyboard/angle entry/Escape focus return, retained rasters and no hover/drag seeking, worker-failure degradation, and Large mobile typography/tap-vs-scroll. The existing 55 unit tests and 22 browser tests remain unchanged. CI captures atlas screenshots with the actual application, worker and Three.js renderer.

Local numerical checks use compiled TypeScript and Node assertions. The offline ChatGPT visual harness uses production HTML/CSS/atlas logic and the real EBM calculation, but a no-op Earth scene and an in-process worker adapter: its captures verify the UI only, not WebGL or actual worker execution. This harness is not part of the repository. Actual dependency/build/browser/worker verification is performed by GitHub Actions; check the run result before claiming completion. Physical iPhone/Safari testing is not claimed.
