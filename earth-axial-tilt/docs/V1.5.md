# v1.5 — Milankovitch Explorer & Earth Synthesis

## Agreed scope: sweep first, not invented Earth history

This release candidate provides a production-built `synthesis-lab.html`, linked
from the main Earth controls and the Feedback laboratory. A parameter sweep is
an ordered collection of hypothetical worlds, **not epochs**. There is no
orbital chronology dataset, no fabricated sinusoidal Earth history, and no
promise to reconstruct actual glaciations. Obliquity 0–90° and eccentricity
0–0.3 include deliberately exaggerated teaching conditions.

The existing v1.3 geography and v1.4 zonal feedback remain separate, named
climate models. Synthesis connects them through their existing validated state
formats; it does not silently claim 2D geographic feedback or feedback colours
on the main 3D globe. Elevation, climate-cloud feedback and physical-iPhone
release acceptance remain outside this milestone. No new runtime dependency,
public deployment or network configuration is introduced.

## Explorer

One of obliquity, eccentricity, or **seasonal longitude at perihelion** varies
across 3–41 conditions. Other background values stay fixed. Seasonal longitude
at perihelion is `perihelion azimuth - axis azimuth`; a sweep changes perihelion
azimuth relative to the retained axis. 0° and 360° intentionally duplicate the
same orientation. With e=0 there is no physically distinct perihelion. At tilt=0
season angles label reference positions, not axial seasons. Axis orientation
is static in each world, not time-evolving precession.

Choose a latitude and northern (90°) or southern (270°) summer reference.
Each condition exposes:

- Daily-mean TOA sunlight on **its own** reference day, not its annual maximum.
- Equinox-to-equinox summer-half duration (not a three-month civil season).
- Time-mean summer-half sunlight and integrated energy, with different units.
- Local annual sunlight and analytic global annual sunlight.
- 365 calendar-day samples and 72 equal-seasonal-angle samples. The latter
  is a parameter×seasonal-angle atlas, **not a climate latitude×year Atlas**.

A and B diagnostic cards use each world's reference day. The annual graph
uses the common 365-day model calendar anchored to day80 spring reference.
These are intentionally different comparisons and are labelled as such.
All numeric exports retain full precision; axis formatting is display only.

## Numerical contract

Inherited `orbitalMoment`, `dayAtSeasonalLongitude` and `dailyMeanInsolation`
remain unchanged. Fixed a=1 au, P=365 days and S0=1361 W/m². Let theta be
seasonal longitude and nu=theta+axis-perihelion. Kepler time weighting is

```
dt/dtheta = P/(2*pi) * (1-e²)^(3/2) / (1+e*cos(nu))²
```

Summer energy uses 360 angular midpoint samples over the chosen pi-radian
sector of `Q(theta) * dt/dtheta`; degrees are converted to radians. Convert
W/m²·model-day to MJ/m² by multiplying by 0.0864. Duration uses the exact
inverse-calendar sector endpoints with periodic wrapping. Mean = energy / time.
A uniform angular mean would give the wrong time mean and is **not** used.
Local annual mean uses 730 equal-time midpoint samples. Global annual mean
is S0 / (4 sqrt(1-e²)), with no per-world solar renormalization.

At fixed e and tilt, rotating perihelion changes summer intensity/duration
but leaves an equinox-to-equinox integrated energy approximately invariant:
r^-2 forcing and r² time weighting cancel. This is a useful analytical
regression, not a prediction of ice melt or temperatures. Numerical quadrature
error and climate uncertainty are distinct.

## Connecting existing labs

`bridges.ts` uses the **existing main schema4 encoder** and Feedback's
`earth-feedbacks` v1 encoder; no hand-written incompatible query aliases.

- 3D Earth receives A and B orbital settings, one shared latitude/longitude,
  the selected material/depth, and A's reference model day. It opens Orbit/A-B
  with the insolation layer. B is NOT re-anchored to its own solstice.
  Existing Compare and selected-longitude geography Atlas semantics remain.
- Feedback receives A's orbit and latitude. Its daily display is an integer,
  so the reference day is explicitly floored to 1–365. It is always the
  uniform-storage **90-band** feedback workspace. Idealized land/ocean links
  use 2.5/50m respectively; Classic/geography links use the chosen zonal depth.
  The UI displays the destination storage and warns that geography is not
  transferred as a feedback model.
- Links restore existing state without auto-playing Earth or running feedback.
- Material, depth and longitude change destination conditions only. They do
  not alter this daily-mean astronomical sweep.

Seven bilingual recipes connect Earth-like teaching settings, zero/90° tilt,
opposite perihelion seasons, material lag, real geography, warm/cold starts and
continued feedback history. The Earth-like recipe (23.44°, e=.0167, peri283°)
is a static teaching configuration, not an ephemeris for a stated date.

## Lifecycle and ownership

One bounded row is evaluated per event-loop turn (setTimeout scheduling), so
Cancel can stop between rows. There is no climate spin-up or Worker in this
workspace. A new run supersedes the old generation. Edits clear old displayed
results immediately; loading valid JSON/hash restores an **idle** experiment.
Malformed input cannot partly mutate an accepted state/result. Canceled means
canceled until deliberate Run. Same-document hash changes use the same validator.

Only one result is retained, at most 41×(365+72) Float64 samples =143,336 bytes
of numeric series. This is not peak browser heap: chart objects/DOM add memory.
A/B selection, metric, language and layout resample/repaint, not rerun. No
history cache, third-party service, telemetry or hidden background task.
A persisted pagehide is retained; real exit disposes timer/listeners/observer.
Unknown/duplicate URL fields, versions/models and oversized settings are
rejected. CSV contains only fixed header text and finite validated numbers.

## Sources and what they do not certify

Primary background checked 2026-09-27:

- [NASA: Milankovitch cycles](https://science.nasa.gov/science-research/earth-science/milankovitch-orbital-cycles-and-their-role-in-earths-climate/)
  motivates separating obliquity, eccentricity and precession.
- [Brian Rose: Insolation](https://brian-rose.github.io/ClimateLaboratoryBook/courseware/insolation/)
  derives daily sunlight and distinguishes calendar time from solar longitude.

These sources do not certify the implementation. Independent algebraic,
numerical, browser and legacy-regression evidence is recorded separately in
[verification](VERIFICATION-1.5-rc.1.md).
