# v0.8 — bilingual guided orbit lab

## Delivered scope

- English and Japanese, including static labels, dynamic summaries, date/month labels, loading/error messages, globe/atlas explanations and accessible control labels. `Language / 言語` is always visible in the main header. Preferences persist when storage is available. Japanese browser defaults to ja; other browsers retain English.
- Contextual `?` buttons for tilt, year, rotation, surface layers, heat storage, temperature model, graphs, comparisons, atlas, science guides and view/quality. Mouse/focus previews a short tooltip; click/tap opens a native dialog with meaning, experiment, observation and limitation. No experiment state is changed by reading help. Escape dismisses a tooltip or the top dialog; original Focus view escape handling is retained.
- Sun-centred orbit overview using the same Earth, textures, markers, daily/instant solar data and thermal field. The existing Earth-centred close-up remains available with its saved camera. View location exits the overview and focuses the real selected geographic point.
- A static procedural Sun surface and additive corona in the overview only. They are decoration, not a stellar model. All sizes and distances are labelled as illustrative.
- Orbit fit and four exact model-quarter buttons (80, 171.25, 262.5, 353.75). Play year moves the Earth at constant circular angular speed with an inertially fixed tilted axis. Play day still freezes the season.
- START_HERE.md provides the handoff entry, file map, workflow, invariants and deferred work. GUIDE.ja.md describes experiments rather than just feature names. Historical version notes remain available.

## Architecture and invariants

`ui/i18n.ts` owns locale; `messages.ts` owns stable English-source keys and Japanese values. Parameterized messages use a tagged template with positional placeholders; static HTML is marked explicitly. No MutationObserver rewrites application output. Underlying city/model IDs and physics modules are not translated. On a locale change only presentation caches are invalidated; the thermal key and physical state remain unchanged.

`scene/orbitLayout.ts` is pure presentation geometry: with Sun direction s, Earth centre E = -14 s. `EarthScene` translates/scales a parent containing Earth and its science guides, without rotating the inertial frame. The scientific matrix remains Rx(obliquity) Ry(spin), and the lighting target follows Earth. The overview uses Earth scale 0.55 and Sun radius 2 for visibility; those sizes never enter the energy model. Existing eight physics modules are unchanged.

The top header, overview toolbar and Focus return note use measured dimensions to avoid long Japanese/Large controls overlapping the visible scene. Focus, text size and quality remain display settings. The close-up now allows a slightly wider distance range (5.1 to 16 display units); orbit view provides the full Sun/Earth relationship without trying to infer a scale orbit from the old Sun direction glyph.

## Verification

Added unit tests cover language selection, reversible translation, placeholder parity, static catalog coverage, bilingual help entries, circular orbit radius, incoming Sun direction, inertial axis agreement with Three.js matrices, and declination agreement at exact seasonal quarters.

Added browser tests cover Japanese dynamic UI and atlas, locale persistence and English return, non-mutating hover/click help and keyboard dismissal, actual renderer changes during orbit travel, playback and fixed axis, close-up return, portrait/Large layout and translated worker errors. The prior full-height Focus assertion is replaced by a stricter usability assertion: the actual drawing area is below the header/toolbar, above the return note, inside the viewport and large enough to view. Both English and Japanese are checked; retaining an 844-pixel canvas behind the enlarged controls is intentionally no longer the contract.

The authoritative full build and Chromium/WebGL suite run through GitHub Actions at the release commit. A sandbox UI-only preview uses a scene double and is only typography/interaction evidence, not a 3D rendering verification. There is still no on-device Safari verification or golden-image baseline suite.

## Deliberately not included

Dual Earth, real-time weather, cloud layer, eccentricity/precession, different planets, station climate calibration and site deployment. No new runtime libraries, no change to the existing climate coefficients, and no external font/texture request.
