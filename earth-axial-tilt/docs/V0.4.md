# v0.4 — reading and interacting with the graphs

## Scope

This is a UI/interaction release built on v0.3, not a new climate model. No physical parameters, climate coefficients, astronomy formulas, location presets, textures or runtime dependency ranges are changed. The current public repository is retained; no website deployment is performed.

## Typography

At a default 16 px root font, Comfort uses 22 px primary values, 14 px labels and notes, and 15 px summaries. Large uses 24 / 16 / 17 px respectively. Major headings keep their own hierarchy. `rem` units respect browser text preferences. Long values are allowed to wrap, not silently truncated. The information-panel background is more opaque and explanatory text has higher contrast.

`earth-lab:text-size` in localStorage records only the display preference. Reads and writes are guarded so blocked storage does not prevent startup. This is not storage of a selected location or a simulation state.

The panels remain scrollable on desktop. At viewport widths of 1100 CSS px and below they flow below Earth, side by side on tablets and stacked below 760 px. This keeps labels readable instead of making two overlays compete for the whole screen. Explore the graph is a navigation shortcut, not a simulation change.

## Responsive SVGs

`chartLayout.ts` computes a plot rectangle from the actual chart box in CSS pixels and its computed text size. Both chart renderers and cursor updates use this common layout. A ResizeObserver invalidates only the drawing layout after the chart dimensions change; the annual data cache is retained. The observer schedules work on an animation frame and ignores unchanged dimensions to avoid resize feedback loops.

Month/time tick density adapts to width; font size does not shrink. Numerical ticks include enough margin for four-digit solar irradiance. Pointer coordinates are mapped through the current chart box and plot bounds, not hard-coded screen coordinates. Scroll offsets and CSS scaling are accounted for.

## Selecting values

Year selects days 1 through 365, rounded to whole days. A selection updates the model's day and retains its rotational phase. Day selects 00:00 through 23:59 at minute resolution. It converts the selected local solar time through the existing `rotationAtSolarHour` function, retaining the orbital day and tilt. At an undefined solar meridian the chart uses nominal rotation hours; this is also exposed in its accessible name and selected-value readout.

Any pointer or keyboard selection pauses playback. Merely resizing text, resizing the window, or navigating to the graph does not change physics or pause the simulation. Graph paths are retained while only the cursor changes, unless data, metric, timescale or dimensions actually change.

Pointer capture keeps a mouse/horizontal-touch drag attached to the graph even when it leaves the plot. Values clamp to the ends. Touch taps select; primarily vertical touch movement scrolls without changing the selected value. Secondary buttons and multi-touch initiation are ignored/cancelled. There is no graph-hover behavior that silently changes the planet.

The focusable graph follows the ARIA slider keyboard pattern: arrows increment/decrement, Page Up/Down use larger steps, Home/End select the endpoints. `aria-valuetext` states the selected date/time, units, and nominal-versus-solar time. A native date/rotation slider is also available; this release does not claim certification across all assistive-technology/browser combinations.

## Verification plan

Existing 29 unit tests and 10 browser tests are retained. v0.4 adds 10 unit tests for layout transforms, pointer bounds, finite inputs, minute/day quantization, keyboard steps, date labels and solar-time/rotation agreement. Seven new Chromium browser tests check real effective SVG font sizes, Large preference reload, panel reflow, pointer capture, keyboard seeking, curve retention, nominal polar time, and native touch tap-versus-scroll behavior. The existing daily-mean reference-line assertion now reads the actual plot bounds instead of the old fixed SVG's coordinates.

In the ChatGPT working container, networking and WebGL are unavailable. UI-only layout/interaction checks use the production HTML/CSS and application/physics code with a no-op scene in a separate, uncommitted test harness. Those captures are not evidence of 3D rendering. Repository CI runs the actual dependency tree and Three.js renderer and saves its own screenshots; a successful run must be verified before calling the release complete. No test harness or vendored fallback library is added to the repository.
