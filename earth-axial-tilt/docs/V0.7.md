# v0.7 — observatory view and local Earth imagery

## Presentation, not a new physics model

- Focus view hides both panels, leaving the globe, date, quality control and a persistent Show controls button. Escape exits only when no modal dialog is open. The view toggle neither resets the camera nor changes the date, tilt, rotation, location, thermal model, heat storage, comparison or playback state. Focus mode itself is not persisted across reloads.
- Eco / Balanced / High set device-pixel-ratio caps of 1 / 1.5 / 2 and anisotropy caps of 2 / 4 / 8, bounded by hardware. The quality preference persists locally when storage is available. They use the same 4K source maps and the same scientific geometry; Eco is not a lower-resolution climate model or a claim of smaller texture memory.
- A portrait viewport widens the vertical lens to maintain a useful horizontal globe framing. Desktop lens and geographic camera focus convention are retained.
- Day and night JPEGs are local build assets, not runtime hotlinks. Vite bundles their URLs for relative-path static hosting. Images are fixed Solar System Scope artwork redistributed via three.js, with CC BY 4.0 attribution in the UI and asset documentation. Sources, original blob hashes and delivered byte checksums are in src/assets/ATTRIBUTION.md.
- Night lights are an additive, Sun-direction-masked layer using the same rotating-frame Sun vector as the astronomy. They can be disabled. They are not a simulation of city growth, habitation or electricity, and do not feed the climate solver. There is no new cloud or weather simulation.
- The artistic atmosphere has a Sun-facing limb instead of an equally bright ring around the night side. Its calculation uses consistent view-space normals and Sun directions. It is a visual approximation, not a radiative-transfer solver.
- Decorative night lights and atmosphere are suppressed in all four scientific surface modes, so they cannot tint those overlays. The base map still provides faint geographic context through the existing transparent scientific overlay.
- Ready/loading/error image status is explicit. Missing images preserve the plain globe and numerical/atlas functionality; they do not quietly substitute remote imagery.

## Rendering and interaction

The scene still receives animation frames for damped OrbitControls, but submits a WebGL render only after camera, physics, texture or size changes. Returning from a hidden tab invalidates the view. ResizeObserver keeps the framebuffer and lens aligned when Focus view changes the canvas size without a browser-window resize. No claim of zero CPU usage is made. Scientific playback still updates the scene normally.

Comfort/Large text, chart scrubbing, the season atlas and the v0.5 thermal solution are unchanged. The quality/focus controls do not live in physical AppState. Browser storage failures leave the controls usable with in-session defaults.

## Verification added

Unit coverage checks allowlisted quality values, DPR/hardware caps, malformed capability reports, and portrait/desktop lens constraints. Browser tests check same-origin asset loading with external network blocked; focus/keyboard return and unchanged science; actual drawing-buffer ratios and persistence; actual renderer-image changes when fixed night lights are switched off; no decorative lights on scientific layers; stopped idle frame submission; a broken local image with working physics/atlas; and Large text on a portrait focus view.

The release's authoritative build and full browser suite run in GitHub Actions with the repository's installed dependency versions. Screenshot artifacts are observations, not golden pixel-baseline regression tests. An on-device iPhone/Safari run is still not covered.
